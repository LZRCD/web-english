# 词环项目复盘与后续事项

> 记录日期：2026-08-01
> 对应路线：[性能、数据升级与异常恢复路线图](./performance-roadmap-gap-analysis.md)

## 一、当前结论

本轮路线图目标已经全部完成并验证：生产构建、77 项单元与结构测试、25 项 Playwright、拆分前后 30 轮性能基线及数据来源复现均已闭环。

当前没有阻塞发布的遗留功能。后续事项属于工程固化、生产环境测量和长期体验优化。

## 二、项目感悟

### 1. 性能优化必须由真实链路数据驱动

文件变小不等于用户操作一定变快。Range 根索引从约 338KB 拆为字母索引后，额外串行请求的固定延迟抵消了部分收益；将 5KB 根映射内嵌后，原生 206 Range P50 才从 14.9ms 降到 10.9ms。

以后做性能判断时，应同时查看：

- 绝对耗时，而不只看阶段占比；
- 首次与重复操作；
- 206、200、损坏和断网等独立场景；
- 请求数量、传输大小和解析耗时。

### 2. 本地应用同样存在分布式一致性问题

多标签页并发写入、旧 revision 覆盖、批量性能样本合并、清空后的旧数据复活，本质上都是一致性问题。浏览器本地存储不能只按单页面状态设计，需要 revision、稳定 ID、锁、合并规则和 tombstone。

### 3. 降级链路是产品能力，不只是异常分支

IndexedDB 禁用、数据库损坏、localStorage 配额耗尽、Range 网络中断、自动播放受阻都可能真实发生。降级逻辑必须做到：

- 不覆盖尚可恢复的原数据；
- 明确告诉用户当前状态；
- 保留恢复入口；
- 有浏览器级测试，而不只依赖单元测试。

### 4. 测试失败需要区分产品问题与测试基础设施问题

首次 Playwright 的 3 项失败来自测试助手在模拟 IndexedDB 失效后仍强制读取 IndexedDB，而不是产品降级失败。排查时应先确认失败发生在产品断言、测试准备还是测试清理阶段。

### 5. 聚合指标可能隐藏真实结论

200 整分片回退、片段损坏和网络中断混入总体中位数后，会改变 Range 占比的含义。性能报告必须保留原始 trace，并按场景、首次/重复和资源缓存状态分组，避免用一个总体数字替代判断。

### 6. 可复现构建需要证据链，而不只是来源名称

“使用 ECDICT、Whisper 和 FFmpeg”不足以复现结果。完整证据至少包括：

- 上游 commit 和源文件 SHA-256；
- 模型 snapshot commit、权重文件 SHA-256；
- 工具版本及二进制 SHA-256；
- 生成报告与最终运行时资产哈希；
- 能证明源文件确实生成当前产物的重建比对。

### 7. 数据版本、代码版本与测试报告必须绑定

即使只补充词典 metadata，也会改变数据内容版本。浏览器验证和性能基线必须记录应用构建号与数据版本，否则历史报告可能被错误地用于当前产物。

## 三、后续事项汇总

### P0：近期工程固化

- [ ] 人工检查当前工作区，按主题建立干净的 Git 提交或里程碑；建议拆分为“性能与 Range”“存储/API/交互”“数据与 provenance”。
- [ ] 在 CI 中固定运行 `npm run lint`、`npm run typecheck` 和 `npm test`。
- [ ] 在发布前 CI 或独立验证任务中运行 `npm run test:e2e`；不要让普通小改动每次都承担完整浏览器成本。
- [ ] 将来源现场校验封装为独立命令，例如 `npm run data:verify`，按固定 commit 下载或定位源文件并验证 provenance。

### P1：生产环境验证

- [ ] 使用生产构建在固定端口 3000 运行一份独立 30 轮基线，与当前开发服务器基线分开保存。
- [ ] 在慢速网络、高延迟和缓存命中三种条件下复核首次查词、音频首播和应用恢复耗时。
- [ ] 将 30 轮性能基线作为发布前或重大数据结构改动后的检查，不必在每次提交运行。
- [ ] 给基线报告增加跨版本对照摘要，直接输出绝对耗时变化、百分比变化和是否超过告警门槛。

### P2：真人体验与长期数据

- [ ] 使用真实手机完成触屏划词、弹窗关闭、音频播放和页面旋转检查。
- [ ] 使用真实读屏器检查学习卡、划词弹窗、设置页和完成摘要的朗读顺序。
- [ ] 使用积累数月的大体量学习记录验证启动、迁移、备份、恢复和清理耗时。
- [ ] 定期抽样检查例句反馈、语义二审和 TTS 回退案例，只有真实失败模式稳定出现时再扩大自动审查范围。

## 四、执行原则

- 先测量，再改变结构。
- 同时保留绝对值、比例和分场景数据。
- 降级时优先保护原始数据和可恢复性。
- 自动测试覆盖机制，真人复核覆盖体验。
- provenance 只记录能够验证的事实，不使用推测值。
- 新报告必须绑定应用构建号和数据版本。

## 五、建议的下一步

优先完成 P0 的 Git 里程碑和 CI 固化；随后补生产构建基线。P2 项目按实际使用反馈逐步推进，不需要阻塞当前版本。
