# WordLoop 自动化迭代 SOP v2

## 核心原则

一次授权可以覆盖一个连续批次。批次内保持：一个纵向目标、最小充分验证、一次精确暂存、一个中文提交、不 push。安全门禁按轮执行，昂贵检查按风险升级，不用轮数和文档篇幅代替价值。

## 两级循环

### 批次基线（只做一次）

批次开始时执行完整 Round 0：

1. 读取授权 Prompt、`AGENTS.md`、本 SOP 和相关调用链；
2. 运行 `scripts/check-iteration-gate.ps1 -Phase Start`，核对分支、完整 HEAD、tracked/index、保护项和固定端口 `3000`；
3. 定义批次目标、最多轮数、硬边界、验证上限和停止条件；
4. 记录可复用证据：相关测试入口、服务状态、既有失败和生成文件。

### 轮次增量（每轮执行）

每轮只做六步：

1. **Delta Gate**：确认 HEAD 等于上一轮提交、tracked/index 无意外漂移、保护项仍未暂存；没有变化时不重读整个仓库。
2. **选择目标**：从批次目标中选一个可独立提交的最小纵向切片。
3. **实施**：只改授权范围；新发现进入候选池，不顺手扩大语义。
4. **分层验证**：先跑最快、最贴近变更的检查；失败即停，成功后按风险升级。
5. **提交**：复核 diff，恢复生成文件，精确暂存，通过 PreCommit 门禁，创建一个中文提交。
6. **判断**：满足继续条件则在同一任务内进入下一轮；否则收尾或 STOP。

只有出现以下情况才重跑完整 Round 0：分支或外部 HEAD 变化、工作区出现归属不明修改、任务恢复自中断、授权边界改变、服务归属不明。

## 验证阶梯

| 级别 | 适用变更 | 必须执行 |
|---|---|---|
| V0 | 只读审计、纯文档 | 链接/命令核对、脚本语法（如适用）、`git diff --check` |
| V1 | 纯函数、测试或局部逻辑 | 最窄定向测试；类型相关时加 `typecheck` |
| V2 | 跨模块逻辑、公共契约、配置 | V1 + `lint` + `npm run test:unit` |
| V3 | UI、持久化、信号流 | V2 + 固定 `3000` 下的精选 E2E |
| V4 | 发布、构建链、依赖或高风险迁移 | V3 + `npm test`（含 production build）+ production smoke/兼容性检查 |

升级规则：只有变更触及更高风险边界、低级验证无法覆盖，或批次最终验收时才升级。不要在同一轮同时运行“定向测试 → 全量 Node → `npm test`”造成重复；`npm test` 已包含 build 和 `test:unit`。

命令连续两分钟无输出时中断并诊断。浏览器服务连续两次失败后停止重启，改用可用静态证据并明确缺口。

## 固定端口服务复用

需要浏览器验证时统一使用：

```powershell
& .\scripts\manage-dev-server.ps1 -Action Start
& .\scripts\manage-dev-server.ps1 -Action Status
& .\scripts\manage-dev-server.ps1 -Action Stop
```

- 固定使用 `127.0.0.1:3000`，不自动切换端口。
- 一个批次内复用同一服务；只在最后一项浏览器验证完成或失败收尾时停止。
- PID、所有权状态和唯一日志写入已忽略的 `.wordloop-runtime/rounds/`。
- 端口被非本脚本管理的进程占用时立即 STOP；不得批量结束 `node`。

## 文档与总控触发

- 普通轮只写短报告：目标、改动、验证、边界、提交、下一步。
- 只有阶段结论变化时更新 `docs/project-evolution.md`。
- 只有下一目标或授权边界变化时更新 `docs/iterations/next-round-prompt.md`。
- 不复制完整命令输出；保留计数、耗时、失败摘要和日志路径。
- 总控不在每个子步骤后重新扫描。它只在开工、范围变化、失败、提交前和批次结束时复核。
- 每五轮或批次结束进行方向复核；价值不足时停止，不机械开启新轮。

## 提交门禁

1. 检查 `git diff --check` 和实际 diff；若 dev/build 改写 `lib/build-info.generated.ts`，在暂存前恢复。
2. 只用精确文件名暂存，禁止 `git add .`、`git add -A`、`git commit -am`。
3. 运行：

   ```powershell
   & .\scripts\check-iteration-gate.ps1 `
     -Phase PreCommit `
     -AllowedPath @("精确文件一", "精确文件二")
   ```

4. 核对 `git diff --cached` 后创建一个中文提交，不 merge、不 push。

## 继续与停止判定

同时满足以下条件才自动进入下一轮：目标仍在同一授权批次内、证据充分、无外部漂移、无新增高风险决策、下一切片有明确用户价值。

任一情况立即 STOP：需要扩大产品语义或授权；生产数据/schema/version/store/domain 变化；无法区分新回归与基线失败；需要猜测历史或降低产品门槛；固定端口被非项目进程占用；保护项/工作区归属不明；批次目标已完成或继续价值不足。

STOP 必须报告：已完成、未完成、原因、Git/服务现场和准确恢复入口。
