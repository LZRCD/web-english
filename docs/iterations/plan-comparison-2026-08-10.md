# 竞品提升方案 vs 开源参考方案 对比与合并路线

> 对比日期：2026-08-10 ｜ 分支：`codex/follow-up-hardening` ｜ 性质：只读对比文档
> 对比对象：
> - A：`docs/competitor-research/提升方案-2026-08-10.md`（12 个竞品官网/商店描述 → 功能路线图）
> - B：`docs/iterations/github-reference-research.md`（8 个开源仓库源码 → 工程范式调研）
> 现状核对：已实读 `lib/weak-signals/`、`lib/learning.ts`（ReviewEvent）、`app/api/` 与 `app/components/HistoryView.tsx`，结论落地到当前代码。
> 本文不代表已授权实施任何代码修改。

---

## 0. 一句话定位

- **A 竞品方案 = 加功能的路线图**：照竞品功能清单逐项补齐内容与形态（词汇量测试、极速刷词、短文填词、词根助记…），批次清晰、可直接投给编码 agent，**几乎不动架构**。
- **B 开源方案 = 改地基的调研报告**：从 Anki / ts-fsrs / 沙拉查词等源码提炼工程范式（事件溯源、统计口径、lapse/leech 复发），**明确声明"未授权实施、仅作候选池"**。

两者不是竞争关系，而是"**补什么**"与"**怎么建得对**"的分工。重叠与冲突点很少，但合并时需要一套取舍规则（见 §6）。

## 1. 维度对比

| 维度 | A 竞品方案 | B 开源方案 |
|---|---|---|
| 依据 | 12 个产品官网 / App Store 文案（功能表象） | 8 个开源仓库实读源码（工程范式） |
| 目标 | 追平 / 超越竞品功能清单 | 修对调度、统计、数据模型的正确性 |
| 批次 | P0 纯本地 6 项（2-3 天）→ P1 AI 3 项（3-4 天）→ P2 真题库（等数据） | P0 事件溯源双表 → P1 lapse/leech → P2 划词 / 续练 / 降级 → P3 同步 / PWA |

| 交付形态 | 可直接粘贴的 Prompt A / B / C | 优先级建议 + 源码索引，需自行落地 |

## 3. 现状核对（两份方案与当前代码的贴合度）

| 现状（2026-08-10 实读） | 对 A 的意义 | 对 B 的意义 |
|---|---|---|
| `lib/weak-signals/`：完整薄弱画像（detection / projection / strategy、lapse 维度、复发率跟踪、维度化处置） | **"薄弱词队列"不是空白地**，新增入口必须接入既有 projection，不能另建存储 | B P1 的"lapses 累加器派生"理念**已落地**；只剩"leech 阈值复发"可补，且 A/B 用词需统一 |
| `ReviewEvent` 已是追加式事件日志（id / rating / kind / intervalMs / dueAt / reviewedAt / recallMs / section / unit） | 直接可写新统计 | B P0 是**补强**而非从零改造：缺 `intervalBefore / difficultyAfter` 快照与"只记账 vs 影响调度"分层谓词 |
| `app/api/`：coach / enrich / lookup / sense-frequency 四条 AI 管线，含缓存与降级 | A P1 三个 AI 功能直接仿照，风险低 | B §6.4 三层降级**大部分已存在** |
| `HistoryView.tsx` 已有周报统计 | P0-6 图表复用同一数据源，须数值一致 | B §7.3 口径可直接作为图表实现依据 |
| 划词已存在（`lib/selection-lookup.ts`） | — | B P2 划词事件流属增强，非新建 |
| 冲刺已存在（sprint session、`SPRINT_TREATMENT_DIMENSIONS`） | P0-2 极速刷词与冲刺重叠 | B P1"冲刺=参数快照"可作调度统一参考 |
| 低分反馈已模板化（`dc09358` 防泄题修复） | — | B §6.2 防泄题三件套已落地 |

**结论：A 是"新功能"路线，落地路径清晰；B 的 P0/P1 大部分已被现有实现覆盖，剩余是"补字段、补谓词、补阈值"，不该按 B 原文做整表重构。**

## 4. 冲突点（合并时必须解决）

1. **"薄弱词队列"双源风险**：A 在 P0-1/2/3 反复出现"一键加入薄弱词队列"。若落成"独立存储一份队列字段"，将与 `weak-signals` 的事件派生投影形成双源。**合并规则：入口做薄（加入的是"临时学习队列/划词集"，即现有概念），薄弱画像一律走既有 projection，不新增存储。**
2. **极速刷词 vs 冲刺**：A P0-2 本质是冲刺的简化版（两键 + 自动翻卡）。合并规则：复用冲刺会话与评分日志管线，只加"极速"UI 层，避免第二套调度。
3. **图表口径**：A P0-6 未定义"遗忘率/可提取率"口径，若直接按 `rating >= 2` 当"顺利回忆"，会重蹈 ISSUE-CANDIDATE-01。**合并规则：图表口径直接采用 B §7.3（只计影响调度的复习事件、ease==1 记失败），与周报数值同源。**
4. **提醒的边界**：A P0-5 只做提醒，B P3 提示"通知内快速测试"。纯本地 Web 应用下通知内答题受浏览器限制，合并规则：先做 A 的提醒 + 通知点击跳转，通知内测试留作远期。

## 6. 合并路线建议

### 采纳 / 拒绝判定

| 候选 | 判定 | 理由 |
|---|---|---|
| A P0-3 文章批量提取、P0-4 考义高亮 | ✅ 采纳 | 纯本地、用户可见、零架构风险 |
| A P0-6 遗忘曲线 + 压力图 | ✅ 采纳（口径按 B §7.3） | 图表可见价值高；口径必须用事件分层谓词 |
| A P0-1 词汇量测试 | ✅ 采纳 | 无开源参照、纯本地、入口现成 |
| A P0-2 极速刷词 | ✅ 采纳（复用冲刺管线） | 简化版冲刺，只加 UI 层 |
| A P0-5 每日提醒 | ✅ 采纳（先提醒后测试） | 低成本、触达有效 |
| A P1-7/8/9 三个 AI 功能 | ✅ 采纳（仿 sense-frequency + 三层降级） | 复用现有管线，含降级测试 |
| A P2-10 真题例句库 | ⏸ 等数据 | 含金量最高但强依赖数据源 |
| B P0 事件溯源双表 | ⚠️ 降级为"补强" | 现状已接近：只补 `intervalBefore / difficultyAfter` 快照与事件分层谓词，不做整表重构 |
| B P1 lapse/leech 复发 | ✅ 采纳（补 leech 阈值） | weak-signals 已有 lapses 派生，补渐进报警即可 |
| B P2 复习会话续练 | ✅ 采纳 | 本地应用最大流失点，改动小 |
| B P2 AI 三层降级 / 防泄题 | ✅ 已落地（`dc09358` + 现有缓存） | 不再重复实施 |
| B P3 打字/默写模式、错词加权队列 | 🟡 可选 | 拼写客观信号有价值，排 AI 功能之后 |
| B P3 PWA 真离线、全量快照同步 | ❌ 暂不做 | 违背"纯本地、数据安全"产品定位；若要备份，快照导出（数据导出 JSON）先行 |
| A 不建议清单（图片记忆 / PK 排行 / 云同步 / 番茄钟） | ❌ 一致拒绝 | 两文档结论相同 |

### 推荐执行顺序

1. **先收尾遗留问题**（评分语义口径 + 事件分层谓词，B §2.1/§7.3 的答案）——它是图表与周报诚实化的前提，改动小。
2. **A 的 P0 纯本地六项**——用户当天可见、无外部依赖；实现时统一"薄弱词入口走 weak-signals"、图表口径按 B。
3. **A 的 P1 三个 AI 功能**——复用 coach/enrich/sense-frequency 模式与三层降级。
4. **B P2 的复习会话续练**（中断可继续，防"复习到一半关掉重来"）+ **leech 阈值复发**。
5. **A P2 真题例句库**——等 `scripts/kaoyan-corpus/` 数据备齐。
