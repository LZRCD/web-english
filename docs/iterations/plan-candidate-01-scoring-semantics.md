## 1. 问题与目标

### 1.1 问题（来自 lean-v3-remaining-issues.md）

- 页面显示"根据真实记忆感受评分"，但用户不确定四档应依据**查看释义前**还是**查看释义后**的感受选择。
- 降级基线中，模拟用户先看释义再选"认识"，结果仍显示"顺利回忆 95%"；用户无法判断该结果代表真实独立回忆、评分达标，还是仅完成操作。
- 风险：首次用户高估学习效果；指标语言与实际证据不一致。

### 1.2 目标

1. 评分区明确要求依据"看答案前"的回忆状态选择，四档提供简短中文判定说明。
2. 明确披露"顺利回忆"计算口径；`rating >= 2` 只等于"当场达标"，不得表述为掌握、恢复或长期记住。
3. 统计口径加事件分层谓词，把查词 / 猜错排除在成功率之外。
4. 补最窄行为测试 + 定向复测，不改 FSRS 或评分阈值。

## 2. 指定方案

### 2.1 评分区文案（只改 UI 文案，不改评分逻辑）

- 评分引导语改为：**"请依据查看释义前的回忆状态评分"**。
- 四档各附一句中文判定说明：
  - 忘记（Again）＝ 看答案前完全想不起来
  - 模糊（Hard）＝ 看答案前只想起一半 / 不确定
  - 认识（Good）＝ 看答案前能独立想起，但不算流利
  - 熟练（Easy）＝ 看答案前立刻想起，无需犹豫
- 明确披露：页面"顺利回忆"指标口径为 `rating >= 2` 的当场达标率，文案不得出现"掌握 / 恢复 / 长期记住"类表述。

### 2.2 统计口径：事件分层谓词（本轮核心改动）

参照 Anki `has_rating_and_affects_scheduling()`：

- 只有**影响调度的复习事件**（`review`：普通/冲刺答题，推进 FSRS）计入"顺利回忆"类指标。
- `lookup`（查词）/ `guess_mistake`（猜错）是**只记账事件**，排除在成功率分母之外；可触发"软重学建议"，不强制重排。
- 统计一律 `WHERE kind = 'review'` 过滤，另设独立口径指标时使用独立分母，不与 cohort / follow-up / retention / 当前薄弱混算。
- 本步只改**统计过滤与文案**，不改数据表结构；为下一步事件溯源留出 `kind` 字段位。

### 2.3 验证契约

1. Round 0 只读基线：Git 状态 / 分支 / 未提交文件 / 端口 3000 占用。
2. 最小行为测试：断言查词与猜错不进入"顺利回忆"分母；评分区新文案存在；口径披露文案存在。
3. 定向测试 + 精选 E2E（沿用既有 runner，不新增端口，不降门槛）。
4. 不 push；提交一个显式中文 commit（如 `fix: 评分依据看答案前回忆并明确顺利回忆口径`）。
5. 严格全新 profile 盲复测仍受环境阻塞时，如实记录为"自动验证通过、首次用户证明未完成"，不得改写为 PASS。
