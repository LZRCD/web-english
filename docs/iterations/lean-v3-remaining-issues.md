## 2. 尚未处理的产品问题

### ISSUE-CANDIDATE-01：评分语义与结果指标不清

严重度：P1 候选

可见证据：

- 页面显示“根据真实记忆感受评分”，但用户不确定“忘记 / 模糊 / 认识 / 熟练”应依据查看释义前还是查看释义后的感受。
- 降级基线中，模拟用户先查看释义，再按“现在认识”选择“认识”；结果仍显示“顺利回忆 95%”。
- 用户无法判断该结果代表真实独立回忆、评分达标，还是仅完成了操作。

风险：首次用户可能高估学习效果；指标语言与实际证据不一致。

下一轮完成定义候选：

1. 在评分区明确要求依据“看答案前”的回忆状态选择；
2. 四档评分提供简短中文判定说明；
3. 明确披露“顺利回忆”的计算口径；如果实际只依据 `rating >= 2`，不得把它表述成掌握、恢复或长期记住；
4. 补最窄行为测试与首次用户定向复测，不改 FSRS 或评分阈值。

### ISSUE-CANDIDATE-02：首次引导可能在用户操作前消失

严重度：P1 候选，必须先复现

可见证据：降级基线中，引导曾显示“首次使用 · 第 1/3 步”，模拟用户准备点击“下一步”时引导已消失。

证据不足：当前只有一次观察，且当时页面仍在加载。尚不能确认是 hydration、已有状态、浏览器重连、焦点变化还是产品逻辑导致。

下一步：在全新 profile 中延迟数据加载并观察引导是否持续存在。只有稳定复现后才允许修改；不得根据单次报告直接重写引导逻辑。

### ISSUE-CANDIDATE-03：未解释英文与缩写增加理解负担

严重度：P2 候选

降级基线记录包括：`NEW`、`SPACE`、`RETRIEVE`、`LETTERS`、`MEMORY LOOP`、`NEXT LOOP`、`Unit`、`vt.`、`vi.`、`adj.`、`n.`、`NO.`、`E`。

证据边界：多数核心按钮已有中文，用户仍能完成操作；不能把所有英文都升级为阻断。下一轮应只盘点核心流程首次出现、可能承载关键含义的词，并优先补中文解释，不做全站机械翻译。

### ISSUE-CANDIDATE-04：首次任务长度偏高

严重度：P2 候选，需要产品决策

可见证据：首次任务为 20 词，完成后继续推荐再强化 5 词；模拟用户最终完成，但认为重复揭示和评分明显消耗耐心。

证据边界：这是体验取舍，不是功能错误。是否提供 3～5 词首次体验闭环，会改变产品节奏与每日目标语义，未经明确产品授权不得直接实施。

## 3. 尚未完成的验证

### 严格盲复测

当前缺少可创建新 browser `context/profile` 的应用内浏览器接口。新模型会话与新标签页已经证明不等于浏览器数据隔离。

恢复条件：

1. 创建全新的 Codex 主任务/窗口，而不是同一任务中的新子 Agent；
2. 获得不同的应用内浏览器 ID / `codexSessionId`；
3. 首次访问 WordLoop 时没有上一会话的完成页、累计数据和撤销历史；
4. 不通过清除未知数据来伪造空白状态；
5. 若仍看到旧状态，立即 `STOP`。

### 最终全流程

尚未由严格隔离的全新用户完成：

```text
首次进入 → 理解用途 → 开始学习 → 评分 → 强化短题
→ 自然进入独立测验 → 故意答错 → 理解正确答案与解析
→ 完成学习 → 完成复习 → 查看结果
```

页面探索继续遵守：只沿完成当前任务的必经路径、普通用户可见且能理解的入口，或由真实困惑产生的访问动机前进；不得直接输入隐藏 URL、依据源码寻找页面或为覆盖率遍历菜单。

## 4. 推荐恢复顺序

1. 先验证新 Codex 主窗口是否真的提供不同浏览器 profile；不满足则保持 `STOPPED`。
2. 在严格空白 profile 中只复测 `dc09358` 的强化答错路径和相邻正常学习路径。
3. 若修复通过，再执行最终全流程，确认是否仍存在 P0/P1。
4. 只有当前提交闭环后，才从候选池选择下一轮唯一目标；优先考虑“评分语义与结果指标”，首次引导必须先复现。
5. 不自动处理英文全量翻译或首次任务长度，不降低评分、FSRS、测验或产品门槛。
