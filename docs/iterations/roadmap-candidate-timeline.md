## 0. 结论速览

- 候选目标按**依赖 → 风险 → 授权状态**排成串行时间线，一个任务一个子 Agent、一个中文提交、一次总控验收。

- 两个任务受环境/决策阻塞：T4/T6 依赖"全新 profile 隔离验证"解锁，T5 依赖产品决策。
- 时间线是候选路线图，不自动实施；每次批次只取其中 1～3 个连续任务授权。

## 2. 执行模式：一个任务一个子 Agent（串行）

1. **总控（主 Agent）只读**：读文件、跑测试、Git 只读命令；不修改、不暂存、不提交；负责授权边界与验收。
2. **每个任务启动一个新的执行子 Agent**，任务完成即关闭，下个任务再开新的：
   - 上下文干净，任务间不互相污染；适合 T2/T3 这类连续但独立的改动。
   - 跨任务依赖（如 T2 需要 T1 的提交）在任务 prompt 里写明：引用目标提交 hash + 相关文档路径，由子 Agent 现场核对。
3. **每个子 Agent 执行**：Delta Gate → 实施 → 分层验证（V0～V4）→ 精确暂存 → 中文提交 → 评估报告。
4. **总控验收节点**：批次开始；子 Agent 报范围变化或失败；每任务提交完成；批次结束。
5. **不推 push**；保护 `1.txt`、`.zcode/`、架构文档和既有日志。
6. **环境不支持子 Agent 时立即说明并停止**，不得假装委派。

> 备选：同批次内任务强耦合时（如 T2→T3），也可按原协议复用同一子 Agent 连续执行，减少重建上下文成本；跨任务新开子 Agent 适合改动面独立、需要干净上下文的场景。

---

## 3. 每任务验收契约（通用）

- Round 0 / Delta Gate 证据：分支、HEAD、tracked/index、3000 服务占用、上次提交。
- 分层验证结果：定向测试数、typecheck、lint、E2E 数，按 V0～V4 阶梯只做必要层级。
- 提交信息：单个中文 commit，精确暂存（禁 `git add .` / `-A` / `commit -am`）。
- 证据边界：严格全新 profile 盲复测未解锁前，一律写"自动验证通过、首次用户证明未完成"，不得改写为 PASS。
- 指标口径：`rating>=2` 只等于"当场达标"；cohort/follow-up/retention/当前薄弱分母独立，不与"顺利回忆"混算。

## 4. 授权边界

| 类型 | 任务 | 处理 |
|---|---|---|
| 可立即授权 | T1、T7、T10 | 单条批次 prompt 即可启动 |
| 需产品决策 | T5（长度与每日目标语义）、T8（UUID 迁移影响数据） | 先与用户确认再授权 |
| 环境阻塞 | T4、T6（全新 profile 隔离验证） | 保持 STOPPED，解锁后插入时间线 |
| 待授权 | T2、T3、T9 | 按依赖顺序进入后续批次 |

## 5. 批次授权模板

### 单任务（推荐起步）

```markdown
按 docs/iterations/AUTOMATION-SOP.md v2 开启一个新批次：
- 本批次只授权时间线任务 T1（见 docs/iterations/roadmap-candidate-timeline.md）；
- 最多 1 轮；使用风险分级验证；精确暂存、一个中文提交、不 push；
- 完成后评估，但不要自动实施后续候选。
现在执行。
```

### 连续多任务（2～3 个，按序）

```markdown
按自动化 SOP v2 执行连续 N 轮（取自 docs/iterations/roadmap-candidate-timeline.md）：
1. T1：评分语义与指标口径（ISSUE-CANDIDATE-01）；
2. T7：%contextCloze% 挖空导出；
3. T10：README 文档维护。
每轮一个纵向目标、一个中文提交，不 push。
批次只执行一次完整 Round 0，轮间使用 Delta Gate。
每轮结束后自动判断是否仍应继续；若前一轮产生高风险决策或后续目标不再合理，立即 STOP。
现在执行。
```

### 子 Agent 模式（每个任务一个执行子 Agent）

```markdown
使用“子 Agent 执行协议”按 docs/iterations/roadmap-candidate-timeline.md 的 T1/T7/T10 顺序执行：
- 主 Agent 只读总控，启动一个执行子 Agent 负责每个任务；
- 每个任务完成后返回：提交 hash、修改文件、验证结果、证据边界、下一步建议；
- 总控逐任务验收后关闭该子 Agent，再启动下一个；
- 每轮一个中文提交，不 push；保护 1.txt、.zcode/、架构文档和既有日志。
现在执行。
```

## 6. 边界与保护项

- 本文为路线图，不自动实施任何候选；每个任务仍需明确授权。
- 不降低评分、FSRS、测验或产品门槛；不改数据表结构（T2/T3/T8 落地前单独确认迁移范围）。
- `1.txt`、`.zcode/`、架构文档、Typora 日志和历史运行日志保持保护项，不得暂存或修改。
- 现场漂移时升级完整 Round 0 并报告差异，不得跳过证据直接续跑。
