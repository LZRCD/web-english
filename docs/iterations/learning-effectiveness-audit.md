## 第 34 轮修正证据

修改前，同词只要在多个周各有一次冲刺 `rating≥2`，就会同时进入多个周 cohort，4 周展示跨周重复样本；页面又把当前统一薄弱画像写成“复发”，暗示已经恢复后发生了新的历史事件。

修改后：

- 多周序列按 wordId 只归最近一次达标处置周，输入 review 顺序不影响归属。
- UI 统一使用“当场达标”“当前仍薄弱”“当前仍薄弱率”。
- UI 明示“未区分从未恢复与恢复后再次薄弱”。
- 既有单周派生接口、当前仍薄弱词明细和再次冲刺动作保留；不改评分、FSRS、恢复判定或数据写入。

## 第 35 轮修正证据

- `buildSprintEffectiveness.resolvedCount` 仍严格来自本周 `sprint:*` review 中 `rating≥2` 的 wordId 去重；`buildSprintCompletionSummary.resolvedCount` 与冲刺历史 `successCount` 是单次 session 的相同口径。
- 周报标题、指标、4 周说明、每周卡片、冲刺完成页和冲刺历史成功率共 6 个用户入口统一改为“当场达标”；内部字段、评分条件、去重和数值断言均保留。
- “仍需关注”继续来自当前统一薄弱画像，允许与当场达标词重叠；未把它改写成“未达标”。

## 第 36 轮修正证据

- 新增共享纯函数 `buildPairedRecallChange`：目标侧按 wordId 聚合全部合法测时后取词内均值；基线侧只选严格早于边界的最近一条非冲刺合法测时；两侧都有样本才进入配对词分母，最后跨词等权。
- 周报与 4 周趋势的目标事件是对应本地周窗内全部 `sprint:*` review，边界是该窗第一个冲刺事件；完成页目标事件是完整 session 的 review，边界是 `session.createdAt`。两入口共享同一配对规则但保留各自真实目标窗。
- 完成页基线明确排除历史 `sprint:*`；不改写任何历史 review。无配对返回 `pairedWordCount=0` 且两个均值与变化均为 `null`，三个入口均显示“无配对样本”。
- 用户文案统一为“冲刺观察 / 同词配对回忆变化 / 较此前快或慢”，明确配对词数；删除“提升/降幅/冲刺后”因果或时序暗示。
- 纯函数测试覆盖同词两侧、目标词内多事件、跨词等权、最近非冲刺基线、历史冲刺排除、无配对、缺失/非法测时、严格边界和乱序输入；周报、4 周与完成页均有集成/E2E 证据。
- 历史 `recallMs` 覆盖不足只会减少配对样本并诚实显示无样本；没有补写、回填或伪造测时。
