- 分支应为 `codex/follow-up-hardening`。
- 起始 HEAD 应包含第 57 轮“明确清空本机学习记录契约”和其后的“自动化迭代流程提速 v2”提交；启动时读取实际完整 hash，不猜测自引用提交。

- 历史测试数字只作背景，不能替代新 checkout 的当前证据。

## 授权门禁

这是下一轮候选 Prompt，不是自动执行授权。用户未明确授权第 58 轮或等价目标时保持等待，不修改文件、不暂存、不提交、不启动服务。

授权后按自动化 SOP v2 开启新批次并执行一次完整 Round 0：

1. 核对 branch、完整 HEAD、tracked diff、index、`lib/build-info.generated.ts` 和固定端口 3000；
2. 确认 `docs/iterations/round-58.md` 不存在；
3. 保护 `1.txt`、`.zcode/`、架构文档、Typora/历史日志和既有服务日志；
4. 完整读取 `AGENTS.md`、自动化 SOP、本文件、词库加载调用链、错误 UI、启动器和直接测试。

任何现场漂移、归属不明修改或非项目端口占用都立即 STOP。

## 唯一目标

解决“词库读取失败后，用户只能看到笼统错误且不知道如何继续”的问题：

- 在当前界面内提供可访问、可键盘操作的重试入口；
- 错误说明区分用户可执行的修复步骤，不展示内部堆栈或制造一定能恢复的承诺；
- 重试必须复用现有词库加载路径和状态，不创建第二套 loader、缓存或数据源；
- 成功重试后恢复正常学习入口，失败时保持错误信息和再次重试能力；
- 桌面和 320px 手机均无横向溢出。

先建立加载状态、错误来源、现有 fallback 和测试覆盖矩阵。若失败类型无法从现有错误可靠区分，使用通用修复说明，不猜测具体原因。

## 硬边界

- 一个 Round 只处理词库读取失败后的界面内恢复，不实施首次使用引导或 README 启动说明。
- 不修改词库内容、数据 manifest、schema/version/store/domain、FSRS、推荐规则或用户数据。
- 不新增网络词库 fallback，不自动清缓存或删除本机数据。
- 精确暂存、一个中文提交、不 push；build/dev 改写的 `lib/build-info.generated.ts` 必须在最终暂存前恢复。

## 最低验证

1. 词库加载状态和错误映射的定向单测；
2. `npm run typecheck`；
3. `npm run lint`；
4. `npm test`；
5. 固定 3000 下运行失败 → 重试失败 → 重试成功的精选 E2E，并检查 320px；
6. `git diff --check`、精确暂存与 PreCommit 门禁；
7. 更新本轮文档、项目演进和下一轮 Prompt；一个中文提交，不 push。
