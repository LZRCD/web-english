## 2. 关键判定说明（Agent 必读）

1. **不扩展 `ReviewKind`**：继续保持 `"new" | "review"`。lookup / guess mistake / quiz attempt 各有独立事实来源；不得为了图表或新题型把它们伪装成普通评分事件。
2. **评分以项目的 0-based Rating 为准**：`0=忘记`、`1=模糊`、`2=认识`、`3=熟练`。True Retention 中仅 0 失败；不得照抄 Anki 文档中的 `ease==1` 而产生偏移。
3. **任务长度不等于每日新词目标**：`dailyGoal` 继续控制每日新增词，现有 5/10/15/20 只控制一次 activeSession 取多少词。完整队列、剩余量与“今日是否完成”仍由同一 `buildTodayTaskPreview` 派生。
4. **图表必须拆开两种指标**：
   - 复习保持率：仅复习事件，忘记（0）失败，模糊/认识/熟练（1/2/3）保持；
   - 困难率：仅复习事件，忘记+模糊（rating<=1）占比。
   二者都必须展示样本量；无样本返回 `null/—`，不得显示 0%。
5. **未来到期是当前快照，不是承诺**：30 天图只表示“按当前 `nextDueAt`，若中间没有新评分会怎样”；用户继续学习后排程会变化。每日新词只能显示设置目标参考线，不能称为未来实际完成量。
6. **覆盖度自评不是通用词汇量测量**：现有估算假定红宝书层位可形成近似单调掌握边界，但该假设尚无外部校准；结果只能用于书内补漏与方向性比较，不提供置信区间、不表述为掌握或达标。
7. **文章提词不滥用“已掌握”**：候选需区分未学习 / 学习中 / 复习中 / 项目内已掌握；默认可隐藏 `status === "mastered"`，但必须允许查看，且不得等同考试日就绪。
8. **Quiz 新题型沿用现有门禁**：短文填词必须写 `QuizAttempt`，并复用 `shouldApplyQuizToSchedule`；同词同日重复作答不得反复改写 FSRS。
9. **leech 的无存储版本不可手动移除**：第一版只按累计 lapse 阈值派生展示。若产品要求“手动移除且到下一阈值再提醒”，必须另行授权一个可持久化的确认阈值字段及其备份/导入/修复契约。
10. **复习事件快照不进入当前路线图**：不新增 `intervalBefore / difficultyAfter` 批次；历史 `difficultyAfter` 无法可靠回填，现有 True Retention 已可从上一事件派生 intervalBefore。未来若有明确回放需求，只对新事件写可选字段，不伪造历史值。
11. **保留逻辑双层，不做数据库级事件溯源迁移**：当前 `reviews` 已承担只增事实流，`wordProgress` 已承担当前态投影。历史成效指标从 `reviews` 派生，未来到期预测从 `wordProgress.nextDueAt` 当前快照派生；在没有跨设备重放、算法迁移或同步冲突的明确需求前，不拆成新的 IndexedDB 双表，不升级 schema。事件 ID 也不得仅依赖毫秒时间戳并声称“零冲突”；多标签页同毫秒写入仍需沿用现有稳定唯一 ID 与 revision 保护。

### 2.1 证据使用边界

- 竞品官网与 App Store 描述只证明厂商在抓取时声称存在相应能力；用户量、语料规模、记忆事件数和学习效果均未独立验证，不作为验收指标。

- 当竞品对齐、开源范式与本项目真实数据契约冲突时，优先级依次为：用户数据安全与诚实口径 → 当前代码事实 → 可验证用户价值 → 外部对标。

### 3.2 下一目标：P1-7 词根拆解 + AI 助记

**目标**：在不改写红宝书 `root/relation` 源数据的前提下，为当前词提供可验证、可缓存、可降级的 AI 词根拆解与记忆联想。

**共享 AI 契约**：

- 复用现有 `lib/ai-provider.ts`、`api-guard`、超时/重试和密钥缺失处理；不得为 P1 新建第二套 Provider 客户端。
- API 输出必须经过独立、可单测的结构化归一化；限制字段长度、数组数量和响应体大小，非法或不完整结果不得进入缓存。
- 缓存身份必须包含功能 schema 版本、prompt 版本及真实输入身份；旧版本缓存只能显式失效，不能被新 UI 当作当前结果。
- 缓存写入必须沿现有 IndexedDB 一致快照、revision、备份/导入/恢复链；若无法在不新增 store/domain/version 的情况下安全完成，应在该轮 Round 0 后 STOP 并重新授权，而不是静默扩大迁移。
- 未配置密钥、超时、限流、非 JSON、字段缺失和离线均属于正常降级路径；不得覆盖已有合法缓存，也不得把本地模板标成 AI 结果。

**P1-7 实施契约**：

- 新增 `app/api/etymology/route.ts`，返回 `{ breakdown, root, affixes[], mnemonic }`；请求只携带当前词、真实释义及已有 `root/relation` 线索。
- 学习卡通过明确用户动作按需生成；有效 AI 缓存优先展示。无缓存或云端失败时依次降级为红宝书本地 `root/relation`，两者都没有时不显示增强卡片。
- AI 结果只作助记内容，不修改词条、考频、词族、FSRS、评分、薄弱信号或原始词根字段。
- UI 必须区分 AI 助记与本地词根提示，支持加载、重试、降级、键盘访问和 320px；不得在首屏批量请求全部词。
- 纯函数覆盖有效解析、裁剪、非法结果和版本失效；API 覆盖 no-key、限流、超时/错误与成功；E2E 覆盖生成、刷新读缓存、本地降级和无词根静默隐藏。

### 3.3 后续目标：P1-9 短文填词

- 只从当天真实新学事实派生最多 10 个目标词；不得从当前进度反推“今天学过”，不得混入 review 或未来事件。
- 生成 80–120 词考研风格原创短文，每个题目 4 选 1；缓存 key 至少包含本地日期、有序目标词身份、schema 版本和 prompt 版本。
- 复用 `clozeSentence` 的安全挖空语义，但不得把短文填词伪装成现有 `meaning-choice`。若新增 QuizMode，必须同步扩展题目快照清洗、activeQuiz 恢复、`QuizAttempt`、weak-signals、备份和损坏恢复测试。
- 每个空对应一个真实 wordId；作答写入 `QuizAttempt` 并复用 `shouldApplyQuizToSchedule`，同词同日本轮重复作答不得反复改写 FSRS。
- 题面、DOM、aria-label、选项 value、日志和加载占位均不得提前暴露答案；结果页再披露答案、释义和解释。
- 覆盖空目标词、少于 10 词、重复词、跨日、缓存失效、离线已有缓存、生成失败、刷新恢复、每日首次/到期词首次排程门禁和 320px。

### 3.4 后续目标：P1-8 长难句每日一句

- 按本地自然日生成并缓存一条考研风格原创长难句，结构化字段至少包括原句、主干、从句、修饰关系、译文和生成元数据。
- 缓存 key 必须包含本地日期、schema 版本和 prompt 版本；日期切换后不得把前一天内容冒充“今日一句”。
- 离线、无密钥或云端失败时只显示当前日期已有的合法缓存；没有当日缓存则诚实显示暂不可用，不用本地模板伪造当天 AI 内容。
- 朗读复用现有浏览器语音/音频控制能力，不新增音频依赖；必须提供可见文本、暂停/重播和键盘可访问入口，不能只靠音频传达信息。
- 不把原创内容称为真题、历年原句或权威语料，不持久化为复习评分、词条或 FSRS 事实。
- 覆盖本地日期边界、跨日失效、同日复用、离线缓存、无缓存降级、结构解析、朗读不可用、320px 与 200%/400% 缩放。

### 3.5 P1 阶段交付边界

- 固定顺序为 P1-7 → P1-9 → P1-8；三项不是同一个纵向目标，不得在一轮、一个 diff 或一个提交中打包完成。
- 每项开始前重新执行 Round 0，核对 HEAD、tracked/index、受保护文件、Provider 调用链、缓存/恢复链和端口归属；上一项完成不自动授权下一项。
- 每项使用独立红测、聚焦单测、typecheck、lint、unit 与精选 E2E；实际触及 schema/version/store/domain、备份协议或构建链时升级 V4，不通过降低断言规避。
- P1 三项全部独立验收后再更新阶段终局；期间不得顺手进入 P2-11、提醒、真题语料或可选 UI。

### 3.7 可选项（P1 之后按需）

- **极速刷词 UI**：复用冲刺与正式评分；全屏大字、2s/3s/5s 自动翻卡、认识→Good、不了解→Again。

- **错词排序权重实验**：只在有真实离线评估集时比较权重，不凭主观把现有 lapse/lookup/recall 顺序替换为 0.6/0.4。

### 3.8 不做

- 当前不做 `ReviewEvent.intervalBefore / difficultyAfter` 历史回填或专门 IndexedDB 迁移。
- 云同步、PWA 真离线、多端强绑定。
- 图片记忆、PK 排行、番茄钟、学习小组。
- Anki 式 Filtered/Preview/Cram 完整状态机。
- 通知内快速测试或“网页关闭后仍保证提醒”。
- 无来源证明的真题语料抓取或发布。

## 5. 实施契约（每个批次）

- 本文为方案，不代表实施授权；每个目标开始前按 `docs/iterations/AUTOMATION-SOP.md` 执行新的 Round 0。
- 一个批次只做一个纵向目标；精确暂存；一个中文提交；不 push。
- 不删、不迁移、不伪造用户学习数据；可选对象字段必须向后兼容并经过备份导入/导出与损坏恢复验证。
- 指标必须返回 numerator / denominator / 无样本状态；不得用显示文案充当数据协议。
- 不降低产品阈值或删减真实交互前置条件来让 E2E 通过。

- `npm test` 会先 build 并可能改写 `lib/build-info.generated.ts`；只在构建风险需要时运行，暂存前恢复生成噪声。
- 固定端口 3000；启动前识别 PID 和归属，验证后精确停止本项目记录的 PID，不批量结束 Node。
- 保护项：`1.txt`、`2.txt`、`.zcode/`、架构/调研文档、Typora 日志、历史运行日志、未确认 favicon 与爬取脚本不得暂存或修改。
