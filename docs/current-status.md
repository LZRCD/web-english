# 词环 WordLoop 当前状态

> 状态日期：2026-08-03  
> 适用范围：当前 `main` 及其后续维护分支

## 一、总体判断

词环已经完成本地个人背词应用的主要产品闭环，当前阶段不是继续堆叠登录、排行榜或云同步，而是验证长期可靠使用并控制维护成本。

核心原则保持不变：

> 功能可以少，但学习记录不能乱；架构可以轻，但本地数据必须可靠。

## 二、当前架构

- Next.js 16、React 19、TypeScript 5、Vite/Vinext。
- 单页客户端应用，AI API 路由只负责教练、内容补充和语境查词。
- 学习记录保存在 IndexedDB；localStorage 仅作为兼容退路和恢复链路。
- D1 与 R2 未启用，学习数据没有云数据库依赖。
- FSRS 负责排程，完整评分日志作为可迁移、可审计的历史记录。
- 红宝书、词典和音频均使用版本化静态数据与内容哈希。

## 三、已完成能力

- 6550 条原书词目，审计后形成 6549 个独立学习项。
- 今日任务、自由学习、单元/全书乱序、收藏/错词/顽固词/划词集复习。
- 四档评分、撤销栈、FSRS 排程、同词族新词错开、自适应新词量。
- 听音拼写、中译英、熟词僻义和近义辨析测验。
- 学习日历、周报、复习预测和考研日期规划。
- ECDICT 离线查词、红宝书音标、原书音频与 TTS 回退。
- IndexedDB revision 冲突检测、跨标签同步、恢复副本、自动备份和导入保护。
- 生产冒烟、Windows 云端构建、单元/结构测试和 Playwright 测试体系。

## 五、当前维护重点

### 1. 长期数据

维护分支新增确定性压力测试，覆盖：

- 6549 个学习项；
- 26196 条评分记录；
- 5000 条测验记录；
- 收藏、错词、内容缓存、位置和撤销历史；
- JSON 解析与归一化；
- IndexedDB 分域拆装；
- 备份文档序列化和读取。

压力测试用于防止长期使用后评分历史被截断、状态分域丢失、FSRS 卡片数量不一致或大型备份无法读取。它不能代替真实数月数据和真实浏览器存储配额验收。

### 2. 真人设备验收

仍需按 `manual-experience-validation.md` 完成：

- iPad/手机触屏划词、弹窗关闭和横竖屏旋转；
- 原声音频、TTS 和浏览器自动播放限制；
- VoiceOver、TalkBack、NVDA 或 Windows 讲述人；
- 数月真实学习记录的启动、迁移、导出和恢复。

### 3. 代码复杂度

`app/page.tsx`、`useStudyPersistence.ts` 和 `globals.css` 仍然较大。后续拆分应围绕明确业务边界，例如评分与撤销、会话入口、测验写入，而不是单纯追求文件行数下降。

结构重构应与数据可靠性改动分开提交，避免同一 PR 同时改变状态语义、持久化和页面控制流。

### 4. 报告归档

完整性能 trace 体积较大。仓库应长期保留正式摘要和少量里程碑报告，原始 trace 更适合 CI Artifact 或独立归档，避免固定报告与 `latest` 文件重复进入 Git 历史。

## 六、文档使用规则

- 当前状态以本文件、根 README、当前代码和最近 CI 为准。
- `project-assessment.md`、`project-retrospective-and-next-actions.md` 等保留为历史记录。
- 历史文档中的分支名、测试数量、构建号和“待合并”描述不代表当前状态。
- 性能结论必须绑定构建号、数据版本、网络条件和运行模式。

## 七、建议执行顺序

1. 让长期数据压力测试通过云端质量检查。
2. 用真实 iPad/手机和读屏器完成体验验收。
3. 用真实数月备份补充长期数据证据。
4. 单独建立结构重构分支，优先抽离评分/撤销或测验写入流程。
5. 制定性能报告保留和归档策略。
